## WF001 — Inventory Restock Check

**Trigger:** User asks which products need restocking  
**Inputs (Excel):** Product inventory CSV; minimum stock threshold  
**Tools required (Excel):** CSV reader; calculator  
**Decision logic (Excel):** If current_stock < minimum_stock, mark product for restock  
**Expected output (Excel):** List of products requiring restock with current stock, threshold, and suggested reorder quantity

**Parameters the agent extracts from the request:**

- `inventory_path` (string) — Path to the inventory CSV (defaults to today's inventory export) · default `data/inventory.csv`, from attachment/default only
- `threshold_override` (integer) — A single minimum-stock threshold the user explicitly asked for (e.g. "below 20 units"). Omit to use each product's own minimum_stock.

**Settings (decision thresholds, config not code):** `target_multiplier`=2

**Steps → tools:**

| # | Step (Excel) | Tool | Policy |
|---|---|---|---|
| 1 | Load inventory | `load_table` | - |
| 2 | Compare current stock with minimum threshold | `compute_columns` | - |
| 3 | Identify low-stock products | `filter_rows` | - |
| 4 | Calculate reorder quantity | `compute_columns` | - |
| 5 | Generate restock list | `filter_rows` | - |

**Conditions / decisions as implemented:** `current_stock < threshold` where threshold = user override or product `minimum_stock` (equal stock is NOT flagged). Reorder qty = 2 × threshold − current stock, rounded up to the supplier case pack.
